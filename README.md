# 订阅续租期间的推送资料接收

当前收存合作机构的公开订阅说明，来源服务可以驱动真实本地 HTTP 验证与投递。收件服务提供订阅管理与推送接收入口：接入、续租、轮换、停止都与实际资料接收对得上。

## 运行

使用 Node.js 22。依赖版本已锁定，运行、测试和演示不下载任何数据或软件。运行时只使用 Node.js 内置模块。

- `npm test`：执行本地来源交互、收件存储及订阅收件全流程测试。
- `npm run build`：逐个检查模块语法。
- `npm run demo`：启动本地来源与收件服务，跑完接入→投递→续租→轮换→停止→重启的完整流程，打印真实收件与拒绝结果后退出。
- `npm start`：在 127.0.0.1:8080 启动本地来源，PORT 可调整。`GET /health` 返回服务与当前来源版本；原有 `/_health` 仍可使用。
- `npm run inbox`：在 127.0.0.1:8081 启动收件服务，PORT 可调整；INBOX_DIR 指定持久目录（默认临时目录并打印路径）。订阅状态、已收资料身份与拒绝日志都保存在该目录，重启后停止状态不恢复。

容器方式：`docker build -t collection-websub .`，然后 `docker run --rm --network none collection-websub`。镜像构建属于环境准备，运行时不访问公网。

## 项目结构

`src/domain.mjs` 提供当前业务读取入口；`src/inbox.mjs` 是收件服务：订阅管理（接入、续租、轮换、停止、对账）与推送接收入口，约定见 `docs/inbox-contract.md`。`src/client.mjs` 负责人工指定地址的有限大小原始领取；`src/archive.mjs` 保存内容及来源凭据。`provider/` 是独立的本地来源服务，`docs/source-contract.md` 说明它的资料和状态约定。演示使用临时目录，正式接入可向业务入口传入持久目录。

本地服务中的机构、记录和文件都是合成业务资料，不使用真实账号、个人信息或第三方站点数据。当前演示通常十秒内结束，全部本地测试应在六十秒内结束。
